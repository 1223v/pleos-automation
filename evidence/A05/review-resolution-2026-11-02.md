# A05 리뷰 후 조치

[독립 리뷰](review.md)를 받은 뒤 구현자가 한 번의 수정 묶음으로 처리했다. 별도 독립 재리뷰를 받았다고 주장하지 않는다.

| 항목 | 판단·수정 | 검증 |
|---|---|---|
| I1 오래된 이력 조회가 새 요청을 덮어씀 | Important 수용. saved 화면 상태를 동기 조회하고 callback도 직접 처리해 늦은 DAO completion을 제거. 미로딩 저장본은 복사본으로 열어 보수적으로 처리 | history-race-red-2026-11-02.log1FAIL(실제 Room executor 지연) → target-avd-retest-2026-11-02.log의 같은 UI 요청 보존 시험 PASS. 최종 저장은 Compose clock/Room 조건 대기로 확인 |
| 복구 이력 로딩 중 근거 없는 설명 유지 | 근거 완전성 문제로 함께 수정. nullable Flow로 로딩/빈 이력 구분, 준비 전 요청/편집 차단, 결과의 유효성을 row+events에 연결 | evidence-loading-red-2026-11-02.log1FAIL → 같은 로딩 gate와 실제 앱 HTTP·모의 provider·근거1 참조 PASS |
| 자동 시작 명칭 | TIME·탑승을 포괄하는 ‘자동 실행’으로 표현 정리. 실행 당시 상세 trigger 표시는 유지 | 기존 이력 UI 시험에서 원인 표시 확인. 문구 정정 자체를 별도 TDD 기능 구현이라고 주장하지 않음 |
| 중단 이력의 조건 편집 문맥 누락 | I1 경로를 동기로 바꾸면서 이미 로딩된 부분 journal을 전달. 새 결과를 추정하지 않음 | 코드 호출 경로 확인 및 UNKNOWN/부분 journal 단위시험. 이 문장 자체의 별도 AVD 단독 시험은 없음 |

설계 판단: 오래된 snapshot은 복사본으로 편집하므로 최신 저장본에 반영하려면 사용자가 별도로 저장/정리해야 한다. 128개 발췌는 설명 크기를 제한하며 생략한 단계의 원인을 설명할 수 없다는 비용이 있다. 메타데이터/스키마/근거 참조 검증은 실제 AI 자연어 정확도를 보증하지 않는다. 이 제약을 UI와 API 한계에 표시했다.

리뷰에서 별도로 판정하지 않은 사항: A05 직전 서버 전체 diff의 원본 부재(추정 복원하지 않음), 실제 AI 정확도·계정 권한·Pleos SDK 재연결·시트·장시간/절전·release10회. 기존 외부/제품 검증 게이트로 유지하며 이번 로컬 완료 판정에 포함하지 않는다.
