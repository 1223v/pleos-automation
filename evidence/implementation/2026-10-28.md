## 시험에서 발견한 제한과 다음 확인

1. **시트 필수 기능 미검증**: 공개 MOVE callback은 입력값을 돌려주며 위치 변화 증거가 아니다. STOP 요청 간격은 등받이275/293ms, 앞뒤 재시험279/257ms였으나 위치0 유지로 움직임을 증명하지 못했다. SDK의 재연결 queue가 과거 MOVE/쓰기 요청을 처리할 가능성도 소스에서 확인했다. 공개 release 경로만으로 정지·재전송 방지 경쟁을 입증하기 전 제품 이동을 잠근다.
2. **공조 초기 연결·오류 경로 미완료**: 기능 READ_WRITE와 권한만으로 현재값 available이 보장되지 않는다. 후속 Cold boot 뒤 정상 변경을 입증했지만 초기 timeout/unavailable의 단일 원인은 미확정이다. 목표 온도를 실제 실내 온도로 대체하지 않는다.
3. **Console**: 공식 로컬 페이지·catalog·state는 읽었으나 신호 전달이 비활성 상태였다. HTTP 공조 입력은 emulator_inactive를 반환했다. 세션 유지용 보조 프로세스는 자동 승인 검토가 차단하여 실행하지 않았다. 실제 Chrome을 열었지만 Computer Use가 현재 브라우저 URL을 확인하지 못해 Windows UI 조작이 종료됐다. 우회하지 않았다.
4. **시험 도구 보정**: 일반 generic fingerprint만 허용하던 시험은 Pleos/crp_avd/ 공식 이미지에서3개 skipped였다(통과 아님). 이미지 식별 조건을 고쳤다. am instrument의 -e는 runner component 앞에 둬야 한다. 뒤에 둔 회차는 vehicle 쓰기3개가 skipped였고 다시 올바른 명령으로 실행했다.
5. **남은 통합**: 실제 점유 유효성, 주행 전환 중 물리 명령 중단, 시트 연결 실패·복구, Gleo 승인·연동, 외부 계정, 전원 suspend·포커스 경쟁, release 필수10회 및 실제 AI 평가. 실제 속도·기어/편집 UX 전환과30분 타이머는 아래 별도 시험에서 통과했다. 사용자 결정 전 유료 API 호출·외부 등록은 하지 않는다.

브라우저 실패·필수 기능 미검증을 이유로 완료 기준을 낮추지 않는다. 로그의 OK 문자열만 보고 skipped를 통과로 세지 않는다.

## 최신 공식 근거로 좁힌 실패 원인

2026-10-28 공개 릴리스·이미지 피드 재확인 결과 Emulator2.1.0 / Vehicle2.3.2 / NaviHelper3.0.5와 설치 버전이 일치했다. [피드 식별](../W03/current-image-feed-summary.json), 공식 출처 D75~78 참조. AVD 기본 Quick boot를 [Cold boot로 보정](../W03/cold-boot-config-fix.txt)했다. 당시 실행 명령은 이미 -no-snapshot이므로 이 변경이 현재 실패를 고쳤다고 주장하지 않는다. 호스트 GPU는 nvidia-smi 기준 RTX3060 12GB이며 WMI의32비트 AdapterRAM 값을 실제 VRAM으로 오판하지 않는다.

Console 최초 비활성 상태와 달리 후속 [읽기 스냅샷](../W03/console-software-before.json)은 emulator_active·bridge_ready·DDS publisher/subscriber 모두 활성이고 HVAC source=subscription이었다. 활성화 계기는 직접 관찰하지 못했다. 같은 software GPU 실행에서 [공조 재시험](../W05/console-active-hvac-test.txt)은 목표값 null로 BLOCKED였다([관찰](../W05/console-active-hvac-observations.txt)). [시트 재시험](../W05/console-active-seat-test.txt)도 앞뒤 capability timeout·등받이 위치0 유지였다([관찰](../W05/console-active-seat-observations.txt)). 따라서 브라우저 연결만으로 두 기능이 해결된다고 단정할 수 없다.

작업용 AVD만 종료한 뒤 `-no-snapshot -gpu host`로 재시작했다. [부팅 로그](../W03/host-gpu-stdout.txt)는 NVIDIA RTX3060/OpenGL ES translator와34,546ms 부팅을 보여준다. 외부 메모리 import 오류1282가2줄 있었지만 후속 [앱 화면](../W23/avd-host-gpu-screen.png)은 정상 표시됐다. [Console 상태](../W03/console-host-after.json)도 활성 상태였다. **이 조건에서 공조 정상 경로1PASS**,22→23°C 실제 변경을 확인했다. Cold boot와 GPU를 함께 바꿨으므로 GPU만의 인과 효과로 단정하지 않는다. 확인된 조건을 [로컬 AVD 기본값](../W03/host-gpu-config.txt)에 저장했다.

[읽기 전용 추가 진단](../W03/hvac-availability-host.txt)은 capability callback이 늦어4초 제한에서 FAIL이었다. [software 진단](../W03/hvac-availability-software.txt)도 timeout이므로 초기 연결의 일시적 가용성 문제는 남는다. 쓰기 시험 PASS로 이 실패를 지우지 않는다. [host GPU 시트2개](../W05/host-gpu-seat-test.txt)는 앞뒤 capability timeout·등받이 위치0 유지로 모두FAIL이었다([관찰](../W05/host-gpu-seat-observations.txt)). 정상 공조·조명과 달리 시트 이동/정지 정책은 아직 활성화할 수 없다.

사용자도 후속 답변에서 **Console이 열리고 조작할 수 있음**을 확인했다. 이는 브라우저 연결 확인이며 시트 이동 성공의 증거로 확대하지 않는다. [시트 재현 자료](../W05/seat-reproduction.md)를 준비했으며 외부 문의를 발송하지 않았다.

## 현재 산출물 대응 및 점검

후속 사용자의 컴퓨터 사용 요청에서 URL이 확인된 **내장 브라우저 탭**으로 Console 직접 접근이 성공했다. Windows Chrome의 URL 식별 실패를 모든 브라우저에 확대하면 안 된다. 이전 자동 승인 검토가 거부한 세션 유지 보조 프로세스는 여전히 실행하지 않았다.

[주행 입력 검증](../W04/console-driving-verification.md): Console에서 D·ACCEL·BRAKE·P를 직접 조작했다. 앱의 실제 AAOS speedMps=1.6666667461395264/D/UX 제한true, 편집 창 닫힘·초안 보존, 정지/P 이후 편집 복귀 **1PASS**. 실제 앱 상태를 가짜 값으로 덮어쓰지 않았다. 제한 시 DB 완료 전에 저장 성공을 표시하던 코드를 수정하고 그래프+입력 요청을 트랜잭션 저장했다. [입력 복구1PASS](../W23/typed-draft-recreate-test.txt), [관련 UI 회귀4PASS](../W23/draft-ui-regression-test.txt). 주행 중 시스템 차단 화면과 시험 후 P 복귀를 실제 캡처했다.

[최신 제품 빌드](driving-draft-build-2026-10-28.txt)는 debug/androidTest/lint/unsigned release 성공, lint0오류15경고다. 아래 이전 제품 빌드 후 주행·초안 변경도 포함된 최신 APK 해시로 갱신한다. core23/서버10은 해당 로직에 후속 변경이 없어 반복 실행하지 않았다.

[제품 최종 빌드](final-ui-build-2026-10-28.txt)는 core 시험·debug·lint·unsigned release를 포함해 성공했다. 이후 시험 코드만 변경한 [최종 androidTest 빌드](hvac-diagnostics-build-2026-10-28.txt)도 성공했다.
