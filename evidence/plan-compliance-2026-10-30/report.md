# 승인 계획 준수 감사 및 재개 기록

감사 시작: 2026-10-30 KST. 재개: 2026-10-31 KST. 기준은 대화에서 승인된 [최초 구현 원문](approved-implementation-plan.md), [정합성 개선 원문](approved-consistency-plan.md), 프로젝트 R01~R20 / W01~W29 / T01~T45다. 이 원문은 현재 코드에 맞춰 축약된 계획과 별도로 보존했다.

**판정: 빠진 구현과 시험이 있다. 기존의 “승인된 로컬 정합성·TDD 작업 완료” 판정은 철회한다.** 기존 core71/app25/server25 및 AVD 시험 기록 자체를 부정하는 것은 아니다. 그 시험들이 승인 원문의 모든 기능·실패 조건을 다루지는 않았다. “코드 구현이 빠짐”, “코드는 있으나 시험이 빠짐”, “사용자 결정 또는 외부 선행 조건으로 보류”를 아래처럼 분리한다. 누락의 의도나 고의성은 코드만으로 판단할 수 없다.

## 중단 지점과 증거 보존

- 10월30일 세 독립 검토자가 원문과 코드·시험을 대조하고 [core 검토](core-review.md), [Android 검토](android-review.md), [서버 검토](server-review.md)를 남겼다. 이후 보조 에이전트 사용량 제한으로 수정 전에 중단됐다.
- 10월31일 재개 시 [입력 해시](audit-input-manifest.json)의 소스98개가 모두 동일함을 다시 확인했다. 당시 제품 코드는 아직 변경되지 않았다. 복사본은 `.local/plan-compliance-2026-10-30/baseline/`에 보존한다.
- core의 기존 compiled classes로 [읽기 전용 재현](core-readonly-repro.log)을 수행했다. 서버도 가짜 외부 응답과 기존 compiled code로 재현했다. 실제 공급자·차량 명령의 재현이라고 표현하지 않는다.
- 이전 시험 로그·APK 해시를 덮어쓰지 않는다. 이번 수정의 RED/GREEN·빌드·AVD 결과는 별도로 기록한다. 완료 여부는 [현재 TODO](../../13_IMPLEMENTATION_TODO.md)와 후속 검증 장부를 따른다.

## 임의 변경과 승인된 보류의 구분

- 전체 실행 전 시트1회 확인, 열선과 독립 내비, 절전 포함 타이머, Asia/Seoul 예산은 사용자가 승인한 정합성 계획에 있다. 무단 정책 변경으로 보지 않는다.
- 실제 AI 키·예산·활성화 전 무호출, 시트 교정 전 잠금, SmartThings/Spotify/파트너 서비스 보류, 배포·결제·외부 계정 신청 미수행은 승인 범위와 일치한다.
- 같은 release10회·실제 시트·실제 AI가 미완료라는 표시는 기존에도 있었다. 이를 숨긴 전체 제품 완료 선언은 확인하지 못했다.
- 반면 Calendar24시간, 편집60노드, 미디어 stub·설명 API 등 원문에 있는 기능의 누락에는 별도 범위 축소 승인을 찾지 못했다. “구현 완료 후 계정 시험만 남음”으로 요약해서는 안 된다.
- 시험을 사후에 추가한 기존 기능과 실패를 먼저 재현한 수정의 RED→GREEN은 계속 구분한다. 이 감사가 과거 모든 개발을 TDD로 소급 입증하지 않는다.

## 재개 순서

1. A01 실제 재현 결함과 경계 회귀시험 → core 검증.
2. A02 외부 상태/응답 검증 누락 → fake IO·로컬 HTTP 검증.
3. A03 승인 연결·무효화 → 모의 안전 시험, 전체 앱 빌드. 시트 실제 잠금은 유지.
4. A04~A07 누락 기능은 원문 범위를 각각 코드·모의시험·실제환경 시험으로 나눠 구현한다. 필요한 공식 계약이 불명확한 부분만 조사/질문한다.
5. A08 잔여 시험 행렬과 실제환경 게이트를 순차 검증한다. 새 코드의 단위시험 통과를 과거 APK의 AVD 증거와 합쳐 완료 처리하지 않는다.
